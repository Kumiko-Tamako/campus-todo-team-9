# 前端阶段 3 能力补齐设计

## 目标

以远程 `main` 的 OpenAPI 契约为唯一接口依据，将前端从问题浏览 Walking Skeleton 补齐到可演示的问答闭环：回答、投票、评论、采纳、标签和本人声誉，同时保留已有认证流程。

## 范围

- API 层：统一定义问题详情、回答、评论、标签、投票和声誉响应；请求路径与 `openapi.json` 的 16 paths / 17 operations 一致。
- 问题列表：服务端分页，支持 `latest`/`votes` 排序，显示标签；标题搜索保留为当前页内快速筛选。
- 提问：增加最多 5 个标签输入，并将标签随请求发送。
- 问题详情：显示题目标签、题评、回答、答评、净票数和采纳状态；登录用户可回答、投票、评论；题目作者可采纳回答。
- 导航页面：标签目录和当前用户声誉流水；未登录时由路由保护。
- 数据刷新：写操作成功后失效对应问题详情/列表查询，避免页面显示旧快照。

## 数据流与权限

Axios 客户端继续统一注入 access token 并处理 refresh。页面只调用 API 模块，不拼接请求。当前用户由 Zustand 保存，用于显示“采纳”权限；后端仍是最终权限裁决，403/409 以可读错误提示呈现。声誉由后端异步记账，页面显示服务端返回的最终一致快照，不假设投票后立即增加。

## 页面结构

- `QuestionsPage`：搜索、排序、分页、标签展示。
- `NewQuestionPage`：标题、正文、标签。
- `QuestionDetailPage`：问题区、题评、回答列表、回答表单、答案投票/评论/采纳。
- `TagsPage`：目录标签及其导航入口（当前后端只提供目录，不提供按标签筛选接口）。
- `ReputationPage`：当前用户总声誉及流水表。

## 错误和测试

API 错误映射补充 403（无权限）和 409（重复投票/重复采纳）。API 测试覆盖请求路径、请求体和详情归一化；纯函数/页面逻辑测试覆盖分页排序参数与回答响应归一化。交付前运行 `pnpm typecheck`、`pnpm test`、`pnpm build` 和 `pnpm lint`。

## 非目标

远程 `main` 尚未包含的编辑/关闭问题与登录锁定不在本轮实现；它们只存在于未合并的 `origin/chore/block5`。
