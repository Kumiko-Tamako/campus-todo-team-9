## 一、功能概述

提问者可**编辑**（仅标题+正文）与**关闭**自己的问题；关闭为**终态**（backlog 无重开故事）。
关闭后全冻结（2026-09-29 裁定）：**题票/答票/新增回答/题评/答评/采纳/编辑一律 409**；
其中"已关闭禁评"落在既有 v3 裁定 #2（phase3-plan，本迭代随 Q08 落地），"禁新增回答"为 aggregates A01 不变式，
"已采纳答案不可关闭"为不变式 5（Q08 × V03 联动）。

接口：
- `PATCH /api/v1/questions/{id}`（200 / 401 / 403 / 404 / 409 / 422；PATCH 部分更新，至少给一个字段）
- `POST /api/v1/questions/{id}/close`（204 / 401 / 403 / 404 / 409；重复关闭、已采纳均 409）

**决策记录（2026-09-29 裁定）**：① 关闭后边界=全冻结（答票/采纳/编辑均禁）；② 锁定口径与参数（见 5.2 台账）；
③ 编辑范围=仅标题+正文（标签不动，需 TagCatalog 重解析超 3SP 体量）；④ US-A02（回答编辑）不并入本轮；
⑤ 允许改 acceptance-criteria.feature 补场景；⑥ 评论按 phase3-plan v3 裁定 #2 禁评（题评+答评），不翻案。

## 五、并发兜底（条件 UPDATE，本轮自查发现并修复）

实现过程中自查出三类真实竞态（对照采纳 AC-12 先例，全部在库级堵死）：

| 竞态 | 原风险 | 修复 |
|:--|:--|:--|
| 并发重复关闭 | 两路都过内存态检查 → 多路 204 | 关闭 UPDATE 条件 `WHERE status<>'closed' AND accepted_answer_id IS NULL`，rowcount=0 读最新行转译 409 |
| 关闭 × 采纳并发 | 可双成功 → 终态"closed 且有采纳"违反不变式 5 | 采纳侧 UPDATE 条件 `WHERE status<>'closed'`（失败整体回滚含 answer 侧翻转）；关闭侧"未采纳"守卫 |
| 编辑/采纳 × 关闭并发 | 无条件 UPDATE 会把 closed 写回 open（状态回退） | 写入侧条件 `WHERE status<>'closed'`；关闭动作只写 status 列（减少与在途编辑互相覆盖） |

回归用例：`test_concurrent_double_close_exactly_one_204`（20 并发恰 1×204）、
`test_concurrent_close_vs_accept_invariant`（恰一路成功 + 终态互斥）。

**观察点（仅记录，未改）**：同作者并发"编辑 × 采纳"存在内容级丢失更新窄窗（后写覆盖 title/body，双方均 200；无不变式风险，量级低危）；响应未含 `status` 字段（前端如需展示"已关闭"标记，另立故事）。

**既有遗留复核（Q08 定稿）**：多态 votes/comments 无库级 FK、questions↔answers 双向 CASCADE/SET NULL——
本轮未引入任何删除语义，复核结论**维持现状**（无需改动；如需加固另行报批）。
