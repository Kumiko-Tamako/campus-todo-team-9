## 一、功能概述

- **2.5 列表** `GET /api/v1/questions?page=1&page_size=20`：访客可用（无鉴权依赖），按 `created_at` 新→旧分页；响应 `{items, total, page, page_size, total_pages}`；`page<1`/`page_size∉[1,100]` → 422；超总页 → 200 空列表（S-03 约定）；列表条目不含正文（D1 决策）；投票排序迭代 2 不做（S-07 按"未知参数忽略"口径闭环）
- **2.6 详情** `GET /api/v1/questions/{id}`：访客可用；返回 7 字段白名单（含 `tags: []`/`answers: []` 恒空列表，迭代 1 约定）；不存在 → 404 只回"问题不存在"（S-10）；非法 UUID → 路径解析 422（S-11）
- 完成后端到端贯通：注册 → 登录 → 提问 → 列表 → 详情（阶段 2 Walking Skeleton 收口）

### 11.1 观察点（非缺陷，记录备查）

1. **HEAD /questions 与 /health 均 405**：当前 FastAPI/Starlette 版本未为 GET 路由自动注册 HEAD（实测 `curl -I` 两个端点均 405）——HTTP 语义上 GET 应兼容 HEAD，但 405 是干净拒绝、无安全影响；如监控/探活需要 HEAD，阶段 4 在 Nginx 层规范化（`limit_except GET HEAD`）一并解决
2. **X-01 首跑依赖停机暴露的 500**：测试中途 PG 容器停止（Docker Desktop 关闭）时，注册接口返回裸 `Internal Server Error`——服务端日志有完整 traceback、客户端无栈泄露（E-07 无泄露一半达标），但 asyncpg 连接类异常不在既有 400 兜底内，**建议阶段 4 前给 `OSError`/连接类异常加统一友好兜底**
3. **X-07 200 并发连接未触顶**：NullPool 每请求新连接 + PG `max_connections=100`，200 并发 GET 峰值瞬时连接未超限——短查询连接持有时间 <5ms 所致；阶段 4 压测仍需探测长事务场景
