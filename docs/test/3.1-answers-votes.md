## 一、功能概述

登录用户可对问题发布回答（正文 1–5000 字，strip 规范化），可对问题/回答投**赞成或反对票**（direction=up/down，1.3 L144）；同一用户对同一对象终身一票、**不可改票**（v3 裁定 #5：再次投票一律 409）。详情 answers 区实装并按 D2 排序（已采纳恒最前 > **净票数**（up − down，v3 裁定 #1）降序 > 时间正序 > id tiebreaker）；列表新增 `sort=votes` 按净票数排序。投票同步事务写库（D1），`VoteCast` 领域事件随投票发出、留位分支 4 的 Celery 消费方。

接口：
- `POST /api/v1/questions/{qid}/answers`（201 / 401 / 404 / 422）
- `POST /api/v1/questions/{qid}/vote`、`POST /api/v1/questions/{qid}/answers/{aid}/vote`（204 / 401 / 404 / 409 / 422）
- `GET /api/v1/questions?sort=latest|votes`（sort 枚举校验，非法值 422）
- `GET /api/v1/questions/{id}`（answers 区由占位 `list[str]` 实装为 `list[AnswerResponse]`，6 字段白名单）

迭代边界（本期不做）：采纳与评论（分支 2）、关闭态（Q08 迭代 5）、声誉结算消费方（分支 4）、标签（分支 3）。

### 5.3 关键防线实证

1. **并发一人一票**：AV-12 同用户 20 路并发抢投，仅 1 路 204、19 路 409——事前检查存在竞态窗口时**库级复合唯一索引为最终防线**（IntegrityError→AlreadyVotedError→409），与 identity 注册并发兜底同模式
2. **不可改票闭环**：AV-11 异向（up→down）与同向重复均 409，索引不分方向（v3 裁定 #5 的"零成本支撑"实测成立）
3. **净票口径贯通**：AV-15 端到端 3up−1down=2，仓储 CASE-SUM 聚合与详情/排序一致（v3 裁定 #1）
4. **协议层防线复用无死角**：AV-04/05/09/14/17——阶段 2 的四项修复（不回显 input、NUL/surrogate 拒绝、body_limit、extra=forbid）在全部新端点/新参数上零改造生效，无新增 500 面
5. **冒名投票被封死**：AV-05 伪造 user_id 422；路由只取 `user.id`，请求体字段不进入命令

### 5.4 测试过程修正记录

- AV-12 初版脚本误用 **20 个不同用户**并发投同一问题 → 20×204 判 FAIL。复核语义：一人一票约束的是"同一用户同一目标"，多用户各投一票本就应全部成功（AV-15 的 4 人投票即此场景）。修正脚本为**同一用户** 20 路并发后 1×204+19×409 PASS。判定为**测试脚本缺陷，非产品缺陷**。
