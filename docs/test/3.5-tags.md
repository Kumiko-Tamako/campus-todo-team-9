## 二、关键决策与偏差（v6 定稿 → 实施）

1. **双 422 形态如实**：tags 类型/结构/原始数量>20 错=**数组形**（pydantic）；去重后>5、白名单违规=**字符串形**（领域 ValueError）。契约说明速查表两行并列（v6 评审点 1 采纳）。
2. **X-06 真 bug 与 key 列单源**（第九路首跑 FAIL 实证，当日修复）：v6 原设计"lower(name) 表达式唯一索引，与 domain `Tag.key` 严格同键"——**对非 ASCII 不成立**：Python `str.lower` 对 İ（U+0130）全映射→"i̇"（2 码位），PG `lower` 简单映射→"i"（1 码位）。两侧键分歧导致"查不到→插入撞索引→重查仍查不到"的 **400 死路**（该标签永远建不了；İ/i 还会意外互撞）。修复：**归并键落独立列 `key`（应用计算、单一事实源），唯一索引建在 key 列**，彻底消除双实现分歧；`TagModel`/迁移/仓储三处同步，补集成回归 `test_nonascii_lower_divergence_key_single_source`。
3. 错误消息不回显标签值（防 surrogate 编码崩溃族）；savepoint 竞败重查必命中（键单源）。
4. 孤儿标签保留（删问题→边 CASCADE、目录行不回收，v6 定稿）；无领域事件（目录非流水型聚合）；无 NFKC（全角≠半角，两标签）。

## 七、换方法复测：Unicode 等价类差分（第十路 `D:\a_work\bruteforce_42_unicode.py`，2026-09-27）

> 与第九路**正交**：第九路打"控制字符 / lone surrogate / 注入串 / 并发同名 / 大小写混战 / İ-I / 长度数量 / 类型混淆"，本路专打**归并键的等价类闭合性**——用"人眼等价 / Unicode 语义等价"的多编码形式轰同一个词，看目录是否落下视觉近同的多行，以及白名单对 Mark（组合音标）与各类空白的判定是否自洽。

**10 组探针（9/9 执行 PASS，零产品硬缺陷）**

| 组 | 形式 | 实测 | 判定 |
|:--|:--|:--|:--|
| U-01 | NFC `café` vs NFD `cafe`+U+0301 | NFC 201 / NFD **422** | 白名单拒 Mn（设计内）；同一视觉名两种编码结果不同（观察③） |
| U-02 | 首尾全角空格 U+3000 | **201** 且与无空格形式**归并为同一行** | ✗ **与 v6 口径不一致**（口径称"不在白名单→422"，实测 `strip` 先吃掉）→ 发现① |
| U-03 | 首尾 NBSP U+00A0 | **201** 且归并 | 同发现① |
| U-04 | 内部 U+3000 / NBSP | 422 / 422 | ✓ 符合口径 |
| U-05 | 词尾 Σ `ΟΣ` / 显式 ς / 显式 σ | Σ 与 ς **归并**（键 `ος`）；σ 形式**独立成行** | ✗ 等价类缺口 → 发现② |
| U-06 | ß / ẞ / SS | ß 与 ẞ 归并；SS 独立 | ✓ 符合预期 |
| U-07 | 开尔文 K / 埃 Å（兼容字符） | 各自与 ASCII 同键归并（共 2 行） | ✓ 符合预期 |
| U-08 | 全角 Ａ vs ASCII a | 2 行（不归并） | ✓ **设计内**（v6 明确不做 NFKC） |
| U-09 | 零宽空格 / 软连字符 | 422 / 422 | ✓ 符合口径 |

**发现（仅报告，未改产品代码）**

① **口径—实现偏差（低危，二选一即可对齐）**：`Tag` 用 Unicode-aware `strip()`，首尾 U+3000 / NBSP 被吃掉后成合法名 → **201 且归并**；而 v6 口径写"全角空格不在白名单 → 422"。**建议改口径**（粘到空白自动清理更友好），或把值对象 strip 收紧为 ASCII 空白（`strip(" \t\r\n")`）——**需你裁定**。
② **等价类缺口（低危）**：`ς`(U+03C2) 与 `σ`(U+03C3) 在 Unicode caseless 等价下同字（`σ.casefold() == ς.casefold()`），但归并键用 `lower()` 而非 `casefold()` → 希腊语同一词的两种合法拼写落成两行目录。**与 X-06（İ/I）同族、机理不同**：X-06 是"应用 vs PG 双实现分歧"（已修），本项是"`lower` 与 `casefold` 语义差"。改用 casefold 需重估白名单与既有目录数据（**本轮不改，交你裁定**）。
③ **设计后果（记录备查）**：分解式（NFD）输入被白名单拒 → 同一视觉标签名"预组合 IME 可建、分解式 IME 422"；无 NFKC 下全角形独立（U-08）。均为 v6 已定口径的必然结果，非缺陷。

**八、发现①②结案（同日，用户令"低危用最好的方法处理"）**

| 项 | 处置 | 理由 |
|:--|:--|:--|
| ① 口径偏差 | **改口径（A 案）**：行为不动，Unicode 感知 strip 定为正式口径（首尾全角空格/NBSP 清理后归并；内部仅 U+0020）——写入 `Tag` docstring + 回归测试钉死（`test_strip_removes_fullwidth_and_nbsp_edges` / `test_interior_fullwidth_or_nbsp_rejected`） | strip 清理空白对用户更友好（粘贴带空白是常态）；收紧成 ASCII-only 反而制造"看起来一样行为不一样"的新坑 |
| ② σ/ς 缺口 | **定向折叠**：归并键 = `lower()` + `ς→σ` 单字符 translate（**不用 casefold**——casefold 附带 ß→ss、ﬀ→ff 展开，会把"ß"与"SS"误判同名，破坏显示名语义）；存量数据 backfill（`D:\a_work\backfill_tag_keys.py`：先并 `question_tags` 边去重、删冗余行，后 rekey——避免唯一索引占位冲突；键用产品代码 `Tag.key` 单源计算，吸取 X-06 双实现教训） | 只闭合实际会遇到的变体族（希腊语词尾 σ/ς 是 IME 常见分歧），最小语义变更 |
| ③ 设计后果 | 记录备查，不动 | v6 已定口径的必然结果 |

**结案取证**：新增回归 3 条（σ/ς 同键 + ß≠SS 不外溢 + 首尾空白口径），**pytest 232 passed** / ruff 0 / mypy 72 文件 0；backfill `total=51 changed=0 merged=2 remaining=49 bad=0`；:8000 重启后第十路复跑 **9/9 无 DEV/OBS**，库级验证 `ΟΣ`/`ος`(ς)/`οσ`(σ) 三形式归并同一行（key=`οσ`）。

**方法论留档**：首跑以"接受数≥2 且键数>1"作自动告警，产生 **3 条假阳性**（U-06/U-07/U-08 本就应多键）；且 U-05 首版把后缀数字紧贴 Σ 使其非词尾、构造失效。复核修正后复跑方得正确结论——**自动化告警阈值不能替代语义判定**。
